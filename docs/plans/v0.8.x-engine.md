# Plan: v0.8.x — A more accurate engine

- **Status:** Accepted (2026-10-26)
- **Roadmap:** [roadmap to v1.0](roadmap-to-v1.md), v0.8. **Decision records:** [ADR-0037](../adr/0037-referee-not-competitor.md), [ADR-0038](../adr/0038-backtrader-as-reference-engine.md)

## 1. Goal

Make Barloom's own engine more accurate, measured against an established engine. The reference engine is the ruler, not a part of Barloom: it runs in its own environment, and the two exchange only files.

- Under the same assumptions, both engines should produce the same fills and the same daily equity. A difference is a bug, in Barloom or in how the case was set up, and is fixed.
- Where Barloom deliberately models something differently, the difference is documented in a decision record, not tuned away.

## 2. The reference engine

**backtrader 1.9.78.123** (ADR-0038). zipline-reloaded was the first choice, but its storage library publishes Windows wheels only up to Python 3.12; installing it would have meant compiling C code during the install. backtrader is a single pure-Python wheel without dependencies.

It lives in `C:\Projects\barloom-reference\.venv` (outside the repository), installed with `--only-binary=:all: --no-deps` at an exact version. Barloom finds it through `BARLOOM_REFERENCE_PYTHON` or `--reference-python`. Nothing in Barloom imports it, and the test suite does not need it.

## 3. Sub-versions

| Version | Contents |
| --- | --- |
| **v0.8.0 — The cross-check** | `tools/crosscheck/`: a runner that replays a case in backtrader with Barloom's assumptions (signal at the close; at the next open, size to target weights from equity at the open, sell before buying, slip the open price, a flat commission per order, whole shares, buys capped by cash), and a driver that runs the same case on Barloom's engine, compares daily equity and fills within stated tolerances, and writes a report. Cases: buy-and-hold, trend following, equal weight, and recent leader, with and without costs, on the example scenarios. |
| **v0.8.1 — Differences** | Run the cross-check. Fix every difference under the same assumptions; write a decision record for every difference that comes from a modelling choice. |
| **v0.8.2 — Realism that affects verdicts** | Cost and slippage models beyond a flat rate (for example, a spread proportional to volatility, or a minimum commission), selectable per experiment; memory use for long histories. Each checked by the cross-check where backtrader can model it. |
| **v0.8.3 — Performance** | Measured with the scale probes, and improved where it limits real use. |

## 4. Security

- The reference engine is not a dependency and is never imported. The driver starts it as a separate process with `-I`, in a temporary folder, with only basic system variables.
- The runner reads only the case file and the price file it names, and writes only its result file.
- backtrader includes connectors for live brokers; the runner never uses them.

## 5. As built

### v0.8.0 — The cross-check

- Reference environment: `C:\Projects\barloom-reference\.venv`, Python 3.13, containing only `backtrader==1.9.78.123` (installed with `--only-binary=:all: --no-deps`) and pip; no `.pth` files.
- `tools/crosscheck/backtrader_runner.py` (reference side) and `tools/crosscheck/run.py` (Barloom side), exchanging `case.json` and `reference.json` in a temporary folder.
- backtrader settings that match Barloom: `cheat_on_open=True` with sizing in `next_open` from equity at the open; sells submitted before buys in symbol order; `set_slippage_perc(..., slip_open=True, slip_match=True, slip_out=True)`; a flat commission per filled order (`FlatPerOrder`); `set_checksubmit(False)` with the runner computing Barloom's cash cap itself.
- Cases: BuyAndHold and TrendFollower (window 10) on one symbol, EqualWeight and RecentLeader on two, on `steady_bull`, `bull_with_crash`, `sideways_chop`, and `recession_bear`, each without costs and with 7.5 bps slippage and a $1 commission.
- Result on 2026-10-26: 32 of 32 cases match; 5,351 fills; worst relative equity gap 1.97×10⁻¹⁵. A negative control, with the reference's slippage raised to 8 bps, differs from the 18th of January onwards.
- Not yet covered (v0.8.1): volume participation caps, position and cash limits, rebalance intervals, corporate actions, starting holdings, and resting limit and stop orders.

### v0.8.1 — Differences

- New case groups on every example scenario, with 7.5 bps slippage and a $1 commission: `EqualWeight` and `TrendFollower` deciding every fifth session; `RecentLeader` with a two-million-dollar account and a 0.2% volume cap (in `steady_bull`, 464 of 481 orders are cut short by the cap); `EqualWeight` starting with 100 shares of the first symbol; `StopGuard` and `DipBuyer` (`tools/crosscheck/crosscheck_strategies.py`), whose backtrader versions use native `Stop` and `Limit` orders renewed after each close.
- Result on 2026-10-26: 56 of 56 cases match; 9,543 fills; worst relative equity gap 1.97×10⁻¹⁵.
- Differences found: none in Barloom. One in the runner: backtrader calls `prenext_open` at the first bar, so starting holdings were bought a day late until the runner routed it to `next_open`.
- Settings learnt: backtrader's slippage applies to stops when they trigger, as Barloom's does; limit orders need `slip_limit=False` to fill at their price or a better open, as Barloom's do.

Modelling choices the cross-check does not settle:

| Area | Why it is not compared | How Barloom handles it |
| --- | --- | --- |
| Splits and cash dividends | backtrader has no corporate-action model; writing one into the runner would test the runner, not Barloom | Barloom's own tests (`tests/test_actions.py`) and its Feed audit |
| Position and cash limits | Barloom refuses a target that breaks a limit and stops the run, rather than trading differently | Validation tests |
| A stop and a limit both touched in one day | A daily bar cannot show which price came first; Barloom assumes the stop fills first, backtrader follows submission order | Documented in the strategy contract; the cross-check strategies never place both |
| A rebalance and a resting order on the same day | Barloom rebalances first; backtrader's order depends on submission | The cross-check strategies never do both on one day |
| Live Feed minute bars | Out of the cross-check's scope | Live replay audits |

### v0.8.2 — Costs

- `CostModel` (`barloom/model.py`) holds `commission_per_share`, `commission_minimum`, and `slippage_range_fraction`, all zero by default; `cost_model()` (`barloom/config.py`) validates them (finite, nonnegative; at most 100 per share, 100,000 minimum, and a fraction of 1). `RunSpec`, `FeedSpec`, and `SuiteSpec` carry it; Live Feed refuses nonzero values.
- The engine's `_commission`, `_slip`, and `_affordable` helpers are used by the rebalance, resting orders, and starting holdings. Range slippage uses the symbol's previous session; the first session has none.
- The Lab pins only nonzero costs, under `costs`, so a registration without them hashes as before; a regression test checks this.
- Cross-check: 12 new cases (`EqualWeight`, `RecentLeader`, and `DipBuyer` on each scenario, 5 bps slippage, $0.005 a share, $1 minimum, no flat part). backtrader's commission scheme in the runner (`PerOrder`) charges the same. Result on 2026-10-26: 68 of 68 cases match. Range slippage cannot be expressed in backtrader's slippage settings, so it is checked by unit tests only.
- Memory for long histories moves to v0.8.3 with the other performance work.

### v0.8.3 — Performance

Measured on 2026-10-26 with `benchmarks/static_scale.py` (Windows 11, Python 3.14), timings without `tracemalloc`:

| Shape | Replay before | After | Peak memory before | After |
| --- | --- | --- | --- | --- |
| 500 symbols, 252 sessions, every 21 | 1.58 s | 0.74 s | 74 MiB | 64 MiB |
| 100 symbols, 2,520 sessions, daily | 8.55 s | 2.24 s | 125 MiB | 106 MiB |
| 500 symbols, 2,520 sessions, every 21 | 16.3 s | 7.4 s | 521 MiB | 425 MiB |

- Profiling found two costs: a SQLite commit after every session (44% of the daily case) and the CSV loader (two thirds of the default case, through `csv.DictReader`).
- `Journal.checkpoint` now sets a savepoint and commits at most every `COMMIT_SECONDS` (1 second); cell boundaries always commit. `rollback` returns to the savepoint. A killed process can lose up to a second of an unfinished run, which was incomplete anyway. Feed and Live keep their own per-session commits, which their forward guarantees rely on.
- `load_daily_csv` uses `csv.reader`, shares symbol strings and dates across bars, and `validate_bar` checks prices with chained comparisons. Messages and line numbers are unchanged.
- Not changed: the tape is still held in memory as one object per bar, about 340 bytes each. Twenty years of 500 symbols needs about 850 MiB. A columnar tape would roughly halve that, but it touches every strategy-facing history type; it is recorded here for later rather than done in v0.8.
- The probe's earlier timings were inflated about fourfold by `tracemalloc`; it now reports process memory and offers `--trace-memory`.

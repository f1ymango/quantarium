## 1. Goal

Before strangers see Quantarium, every screen, the guided tutorial, and the handbook should describe the product as it is at v1.0.4, read clearly to someone without financial training, and use the name Quantarium throughout. This is a catch-up and polish step, not a feature step.

**Out of scope:**

- How Quantarium is delivered (local web app, desktop app, or hosted dashboard). The maintainer has not decided; keep the local web app as it is.
- New runtime dependencies, new frameworks, or a build step for the frontend. The app stays plain ES modules with the vendored Preact, htm, and uPlot.
- Changes to the engine, the Lab's rules, or results. If a fix would change any result, stop and ask.
- Live Feed controls in the app (Live Feed remains command-line only, as documented).

## 4. Phase 1 — Audit

Serve an empty workspace and walk through the app as a newcomer:

```bash
py -m quantarium serve --fresh
```

Then walk through it again in a workspace with data. The examples and `examples/data/fictional_index` hold only invented prices; import the latter from the Workspace page after copying it under `data/`.

For **each page** — Home, a cell (Overview, Configure, Runs, Timeline, Answers), Static, Feed and the arena, Scenarios (gallery and detail), Lab (Experiments and Supercells), Log, Activity, Workspace, Agents, Inbox, Learn (tutorial, handbook, help topics), and the Assistant panel — check:

- **Accuracy:** every word matches what the page does at v1.0.4; numbers, labels, and defaults are right; links lead somewhere real.
- **Coverage:** each feature in section 2 can be found from the page where a user would look for it, and is explained there or in a help topic.
- **Plain language:** a reader without financial training can follow it. Terms such as Sharpe ratio, drawdown, slippage, survivorship, or deflated Sharpe ratio are explained where they first appear, or link to a help topic.
- **States:** the empty state, loading, an error (stop the server mid-action), and a long list or long names.
- **Defaults:** they are safe and sensible (agent features off, costs, budgets, tiers).
- **Accessibility:** keyboard-only use and visible focus, labels on every control, contrast in both the light and the dark theme, and a narrow window (1024 px wide).
- **Security invariants (AGENTS.md section 5):** pages render model, agent, and file text as text, never as raw HTML, and links built from data stay in-app routes. Do not weaken either; a change that touches them needs a regression test.
- **The guided tutorial, start to finish:** every step's target exists, its wording matches the screen, Resume and Skip work, and finishing adds exactly one working cell.

**Record every finding** in section 8 of this file, as a row: page, what is wrong, severity (high: wrong or broken; medium: confusing or missing; low: polish), and category (**Fix** or **Needs a decision**, per section 5).

## 6. Decision recorded: add a sixth tutorial chapter, "Test it honestly"

The user authorized Codex to resolve architectural choices and record both the choice and alternative. I chose to add this chapter after "The record", using the tutorial's private workspace:

1. Open the Lab and pre-register the tutorial cell against the tutorial market: give the idea a name and keep the default pass rule.
2. Run the frozen experiment, then read the verdict: the cell against buy-and-hold and equal weight, the deflated Sharpe ratio, and the caveats.
3. Register the same idea again on the same market, and see the second attempt marked exploratory, because the data was already used.
4. End with the point of the product: a result is evidence only within its controls, data, assumptions, and attempt history.

**Alternative considered:** keep the Lab only in the handbook to preserve a shorter tour. I chose the guided chapter because pre-registration and the exploratory label are core product distinctions that are clearer when seen in the actual UI. The two practice attempts remain private and are discarded on finish; only the tutorial cell, market, Static result, and Feed practice are promoted.

Constraints: the tutorial runs in its own private workspace and is promoted on finish (ADR-0013); `tests/test_onboarding.py` and `tests/test_tutorial_content.py` cover it; finishing must still add exactly one working cell; a Lab run on the tutorial market must finish in a few seconds.

## 7. Working rules for this step

- **No installs.** Everything needed is in the repository. If a check seems to need a package, ask.
- **No real accounts:** no model API keys, no Alpaca, no agent apps signed in to the maintainer's accounts. Agent pages are checked with agent features off and, if needed, a connection to a local fake.
- **Known gotchas in this frontend:**
  - htm drops the space at a line break inside a template, so keep a sentence that spans markup on one line.
  - `fmt.pct` prints a sign, which is wrong for probabilities; `lab.js` has a local `chance()` helper for them (move it to `ui.js` if another page needs it).
  - Calling `reload()` from a page's `useAsync` returns the page to its loading state and unmounts its children, losing their local state.
- **Verification:**
  - `py -m unittest discover -s tests` must pass. `tests/test_frontend_syntax.py` catches unbalanced brackets in the scripts; `tests/test_tutorial_content.py` and `tests/test_onboarding.py` cover the handbook and tutorial.
  - Check every changed page in a browser. Without one, Edge can capture a page from the command line (Windows path shown):

    ```bash
    "C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless=new --disable-gpu --window-size=1440,900 --virtual-time-budget=8000 --screenshot=page.png "http://127.0.0.1:8765/#/lab"
    ```

  - Keep screenshots out of the repository unless they replace `docs/images/`, and then only from a workspace of invented data.
  - The maintainer walks through the finished tutorial once, by hand.
- **Versioning:** set **1.0.5** in `pyproject.toml`, `quantarium/__init__.py`, the README's `**Version: 1.0.5.**` line, and a new top changelog heading `## v1.0.5 — date`; `tests/test_version.py` checks them. No **Results change** is expected; if one appears, stop and ask. Do not tag: the maintainer says when to ship.
- **Commits:**
  - Use the identity in `AGENTS.md`, scan the staged diff, and run `git fetch` before pushing.
  - Small commits by area are fine; the version is set in the last one.
  - Record what you did in the changelog and in section 9 below.

## 9. As built

Implemented by Codex (GPT-6) on 2026-10-27. Added the Lab chapter with first-run registration, a control comparison, deflated Sharpe context, a second attempt on the same data marked exploratory, and a closing evidence-limit statement. The UI uses the ordinary registration and run actions, with tutorial-specific prefilled values. The two Lab attempts remain in the private tutorial workspace; completion promotes the cell, fictional market, and Static/Feed results, while discarding the Lab ledger and `runs/lab.sqlite`. Handbook numbering and Learn copy now describe the six chapters. `docs/frontend-spec.md` is marked as a historical design record.

The shared **Do it for me** handler now waits for its visible target, grants that target input before activating it, and reports missing or disabled controls instead of silently failing. Lab waits for its three data sources before showing registration or an empty state. The README's tutorial and handbook counts, timing, and retention description now match the app.

**Decision:** Add the guided Lab chapter after “The record,” following the user's instruction to resolve decisions and record alternatives. **Alternative:** keep the Lab handbook-only to preserve a shorter tour. The guided chapter was chosen because registration, controls, and the exploratory label are central product concepts and are clearer in the live interface.

**Verification:** The full suite passed on the final application files: 527 tests run, 11 skipped, using the bundled Python runtime and `-B -m unittest discover -s tests`. The focused tutorial, syntax, version, and onboarding group also passed (21 tests). In a fresh fictional workspace, headless Edge completed the entire six-chapter tutorial through all 49 actions, using **Do it for me** on every available step; it reached the finale and promoted one cell without promoting `runs/lab.sqlite`. A second replay reached the final “Evidence has limits” dialogue after 48 actions; its spotlight surrounded the visible warning that the second Lab run was exploratory. A delayed local Lab API response showed the loading state until data arrived, then the registration form, with no premature empty state or browser exception; a simulated API error showed an error rather than an endless loader. The handbook opened with Enter, kept keyboard focus inside, closed with Escape, and returned focus to its trigger; it listed 16 chapters. A populated-workspace smoke check opened 17 routes in light theme without browser exceptions, alerts, or horizontal overflow; six main routes at 1024 px in dark theme had no horizontal overflow. No packages or external accounts were used.

**Remaining:** The maintainer still needs to walk through the tutorial once by hand. The route smoke checks do not cover every interactive state, Assistant behavior, or measured color contrast; those remain unverified. Keyboard use was checked for the handbook dialog, not for every page.

# Plan: v0.9.x — Compatibility with the user's own data

- **Status:** Done (v0.9.0–v0.9.5, 2026-10-26)
- **Roadmap:** [roadmap to v1.0](roadmap-to-v1.md), v0.9. **Decision records:** [ADR-0037](../adr/0037-referee-not-competitor.md), ADR-0039 (changing universes, written with v0.9.1)

## 1. Goal

Quantarium supplies compatibility, not data. Users bring research data they have bought or gathered, and their own trading history, and Quantarium makes them easy to use and says honestly what they can and cannot support.

Three things stand in the way today:

- **The format.** Only single-symbol downloads from Yahoo, Nasdaq, and Stooq can be imported. Research data comes as many symbols, with delisted securities and index membership, and Quantarium has no place to record either.
- **The engine.** A Static tape must have a bar for every symbol on every session. Real survivorship-free data is full of symbols that list late, delist, or move in and out of an index. Such data cannot be replayed at all.
- **The verdict.** The Lab cannot tell data that includes the losers from data that only holds today's survivors, and it cannot tell a universe chosen with hindsight from one chosen as of each date.

## 2. Decisions

Made with the maintainer on 2026-10-26:

| Topic | Decision |
| --- | --- |
| Paper trading | **Not in v0.9.** v0.9 adds brokerage market data only. Paper trading becomes the first step of the post-v1.0 trading plan, designed together with per-order confirmation and the change to `AGENTS.md` section 1. |
| Futu OpenAPI | **In its own environment**, like the backtrader cross-check. `futu-api` is installed only there, by the maintainer; a bridge script writes plain files that Quantarium reads. Quantarium gains no dependency. |
| Research data formats | **Quantarium's own documented format** only. Vendors' exports are converted into it by the user; specific vendor layouts can come later. |
| Brokerage history | **A generic trades CSV** (date, symbol, side, shares, price). Broker-specific statements can come later. |

## 3. Sub-versions

| Version | Contents |
| --- | --- |
| **v0.9.0 — The data format** | `quantarium-data-v1`: a folder with `prices.csv` (long format; a symbol may start late or stop early), optional `delistings.csv` (symbol, date, final price, reason), optional `membership.csv` (index, symbol, from, through), and `source.json` (who supplied it, its license note, and the user's survivorship declaration: `survivorship_free`, `survivors_only`, or `unknown`). A validating reader, bounded and fuzzed like the v0.5 parsers. `quantarium data check` and `quantarium data import`, which builds a historical scenario recording the source and declaration. |
| **v0.9.1 — Changing universes** | The engine replays tapes in which symbols list, delist, and change index membership. A symbol is tradable only between its first and last bar; a gap inside that span is still an error. On a delisting, a held position is closed at the delisting price (or the last close if none is given) and the cash credited, with a `delisted` event. `context.universe` gives the tradable symbols, and, for a cell that names an index, the members as of that session; weights on symbols outside it are refused with a clear error. Starting holdings and resting orders on a delisted symbol are cancelled. Cross-checked against backtrader for late listings and delistings where it can express them; ADR-0039 records the rules. |
| **v0.9.2 — Survivorship in the Lab** | The Lab pins each scenario's survivorship declaration. A verdict on data not declared `survivorship_free` carries a survivorship caveat. A cell with a fixed symbol list on historical data carries a selection caveat ("a list chosen today"), unless it trades an index's members as of each date. Evidence reports show both. |
| **v0.9.3 — Your own track record** | `quantarium decisions from-trades` turns a generic trades CSV into a decision file of orders: a trade filled on a session becomes an order decided at the previous close, filled at Quantarium's next open with the experiment's costs. The report compares Quantarium's fills with the real ones (the implementation gap). Deposits, withdrawals, and corporate actions in the account are listed as limits. As for all decision files, the Lab's verdict stays capped at `unknown`. |
| **v0.9.4 — The Futu bridge** | `tools/futu_bridge/`: a script run with the bridge environment's Python and `-I`, which asks Futu's local OpenD gateway for daily bars and writes a Static price file or appends to a Feed price file. Quantarium reads only that file, through the existing CSV Feed provider. Documented setup; the conversion is unit-tested with fake quote data. The maintainer runs the real check. Alpaca's daily and minute data, already supported, are documented next to it. |
| **v0.9.5 — The app and the handbook** | Importing data and trades from the app, survivorship and selection shown on scenarios and verdicts, and a handbook chapter. |

## 4. Security

- Every new reader handles untrusted files: sizes, row counts, symbols, and numbers are bounded; `NaN`, infinities, and duplicate keys are refused; reading never runs code. New misuse tests go in `tests/security/` on the `MisuseCase` harness.
- Imported files are copied into the scenario with their hashes; a scenario whose files change no longer verifies.
- `source.json` is data the user declares. Quantarium records it and shows it as declared; it never treats a declaration as verified.
- The Futu bridge is not a dependency and is never imported by Quantarium. It runs as a separate process with `-I` and only the variables it needs; it talks only to OpenD on a loopback address and writes only its output file. It never calls trading functions; the bridge refuses to start if asked for a trade context.
- No real accounts are used in development or tests. Brokerage connections are checked by the maintainer.

## 5. As built

### v0.9.0 — The data format

- `quantarium/userdata.py`: `read_source`, `read_user_data` (returns the tape, each symbol's span, delistings, membership, file hashes, and warnings), and `import_user_data`. `quantarium data check` and `quantarium data import` in the CLI.
- `load_daily_csv` gained `symbols=None` (keep every symbol) and `every_session=False` (symbols may come and go); the defaults keep the Static rule that every symbol trades on every session.
- Scenarios accept `delistings.csv` and `membership.csv` as listed, hashed files, and expose `survivorship` from their provenance (`method: import-data`). The Lab's data family for an import is the hash of its `prices.csv`.
- Decided while the maintainer was away: `source.json` is required, so every import carries an explicit supplier and declaration (`unknown` when omitted); a symbol that stops without a delisting row is a warning, not an error, because vendors often omit them; index members without prices are a warning for the same reason.
- `examples/data/fictional_index` is generated from a seed and contains invented companies only.
- Tests: `tests/test_userdata.py` (format rules, import, tampering) and `tests/security/test_user_data.py` (fuzzed source, prices, delistings, and membership; hostile strings in every field; duplicate keys, `NaN`, and oversized files).

### v0.9.1 — Changing universes

- `RunSpec.changing_universe`, `delistings_path`, and `membership_path`; `CellSpec.index`. Suites set them for scenarios with a survivorship declaration (imports); Static configs through `changing_universe`, `delistings_path`, or `membership_path`.
- Engine: `Universe` (spans, delistings, membership), `_universe_tape` (the whole file's calendar), `CellRuntime._close_delisted`, and `process_day(..., universe=...)`. Rules in ADR-0039.
- `userdata.symbol_spans`, `parse_delistings`, `check_delistings`, and `parse_membership` are shared by the importer and the engine.
- Decided while the maintainer was away, differing from the plan above: weight outside the universe stays in cash and is recorded (`outside_universe`) instead of failing the cell, matching how the engine already treats unpriced symbols and letting a one-symbol cell survive a delisting; starting holdings that do not trade on the first session are an error rather than silently cancelled.
- Not cross-checked against backtrader, which has no delisting payouts or index membership. Instead, the changing-universe path is required to replay fixed universes event for event as the classic path does (all example scenarios and strategies), and the new rules are tested on the example index.
- Found during testing: taking the calendar from the cell's own symbols ended a run before an all-delisted cell's payout. Fixed by using the whole file's sessions; `test_weight_outside_the_universe_stays_in_cash_and_is_recorded` guards it.

### v0.9.2 — Survivorship in the Lab

- Pins gain `survivorship` for imported scenarios only. Rows report `_survivorship(pin)`: the declaration, `not_declared` for other real-price data, or `None` for synthetic markets.
- `_data_caveats`: the survivorship caveat for real-price scenarios not declared `survivorship_free`, and the selection caveat for a candidate without `index` on real-price data (not for finished decision files, which are already exploratory).
- Decided while the maintainer was away: both are caveats, not changes to the verdict's status. The declaration is the user's and cannot be verified, so it should inform the reader rather than gate the result; the DSR already gates "supported".
- Lab controls copy the candidate's `index`. `CellLibrary` keeps `index` in specs and entries.
- Suite caveat `historical_declared_free` replaces the generic survivorship sentence for declared-free imports.
- Tests: `tests/test_lab_data.py` runs real Lab experiments on the invented index, declared free and declared survivors-only.

### v0.9.3 — Your own track record

- `quantarium/trades.py`: `read_trades`, `trades_to_decisions`, `write_decisions`, and `fill_gap`; CLI `decisions from-trades` and `decisions gap`.
- Decided while the maintainer was away: trades are netted per day and symbol (daily bars cannot order intraday fills), and each order carries the real average price as its `price` and in its `tag`, so the decision file alone shows what really happened. The NYSE calendar is the default; `--prices` uses a price file's sessions instead (for other markets or synthetic scenarios). The calendar span is bounded at 60 years.
- No change to the Lab: finished decision files stay capped at `unknown` (an `AGENTS.md` invariant).
- Tests: `tests/test_trades.py` (rules, netting, calendar, a full replay with a known 1% gap) and `tests/security/test_trades.py`.

### v0.9.4 — The Futu bridge

- `tools/futu_bridge/bridge.py`: `parse_codes`, `to_rows`, `write` (new file or `--append`), and `fetch` (OpenD's `OpenQuoteContext.request_history_kline`, paged, daily). `futu` is imported only inside `fetch`, so the module loads without it.
- Decided while the maintainer was away: `--adjust forward` is the default, matching `import-bars` and the `csv` Feed, which have no corporate actions; `--append` keeps existing rows as first seen rather than rewriting them, as the Feed pins first-seen bars. No `futu-api` version is named: the maintainer picks and audits one when setting up the bridge environment, following `AGENTS.md` section 2. Nothing was installed.
- Tests: `tests/test_futu_bridge.py` (no `futu` import, no trading names in the source, loopback only, code mapping, a written file that `load_daily_csv` reads, append behaviour, bad candles).
- Not done: a real OpenD run. The maintainer runs the first one.

### v0.9.5 — The app and the handbook

- API: `data-check` and `trades-convert` (commands) and `data-import` (job), refused to agent tokens both by the operation table and explicitly. The workspace overview gains `data_folders` and `trade_files`; scenario summaries gain `survivorship` when set; the scenario route returns `null` for days a symbol does not trade.
- App: an Outside data panel on the Workspace page, survivorship badges and notes on scenarios, and an Index field in a Complex cell's Portfolio rules. Checked in the browser on a workspace with the example index and a trades file: import, conversion, the scenario chart with listings and delistings, and handbook chapter 15.
- Decided while the maintainer was away: trades files and data folders live under `data/`, not `decisions/`, whose scan would list a trades CSV as a broken decision file; `AGENTS.md` gains an invariant row for outside data (a strengthening, with its regression tests in `tests/security/test_outside_data.py`).

# Plan: v0.3.x — Model connections

- **Status:** Accepted; decisions in section 6
- **Date:** 2026-10-21
- **Scope:** Make the built-in assistant compatible with as many models and agent runtimes as possible, through two provider-neutral ports instead of per-vendor code. Then add the providers the user asked about, one sub-version each: Claude subscriptions, OpenCode, GitHub Copilot, Grok, and Gemini.

## 1. Goal and principles

Quantarium will be open source, so connections should be **compatible with models rather than engineered around vendors**:

1. **Ports speak protocols, not brands.** A connection names a *protocol* plus settings (endpoint, model, where the key is). Vendor support is data, not code: a preset is a few lines that fill in defaults.
2. **Any compatible endpoint or runtime works on day one,** including ones Quantarium has never heard of, through a "Custom" option. Presets are a convenience.
3. **Nothing about safety is per-vendor.** Every port ends at the same agent checkpoint (`Api.agent_call` or `agent_request`): tiers, path rules, holdout, budgets, sandbox, Inbox, audit log. A new provider cannot weaken it.
4. **Subscriptions only through the vendor's own unmodified app, and only where the vendor's terms allow it.** Quantarium never signs in to a plan itself, never reads a plan's tokens, and says plainly when a vendor's terms are unclear.

### Protocols that make universal ports possible

- **OpenAI-compatible Chat Completions** is the de facto standard for model APIs. Endpoints using it:
  - OpenAI, Gemini (`https://generativelanguage.googleapis.com/v1beta/openai/`), xAI (`https://api.x.ai/v1`), and OpenCode Zen;
  - OpenRouter, Groq, Mistral, DeepSeek, and GitHub Models;
  - local servers such as Ollama, LM Studio, and vLLM.

  ([Gemini OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai), [xAI via Agora](https://docs.agora.io/en/conversational-ai/models/llm/xai))
- **The Anthropic Messages API** is the other widely implemented shape. Claude uses it, and so do several gateways.
- **The Agent Client Protocol (ACP)** is an open JSON-RPC protocol between a client and a coding agent, like LSP for agents.
  - The client starts the agent as a subprocess on stdio.
  - `session/new` passes the MCP servers the agent should use.
  - `session/prompt` and streamed `session/update` events carry the turn, and `session/request_permission` asks the client before tool use.
  - Native ACP agents: Gemini CLI, OpenCode, GitHub Copilot (preview), Cursor, Kiro, Qwen Code, Goose, Mistral Vibe, Kimi CLI, and others.
  - Through adapters: Codex (`codex-acp`) and Claude (`claude-agent-acp`, built on the Agent SDK).

  ([ACP agents](https://agentclientprotocol.com/get-started/agents), [session setup](https://agentclientprotocol.com/protocol/v1/session-setup))
- **Claude Code's own headless mode** offers what a bridge needs: `-p --output-format stream-json`, `--mcp-config` with `--strict-mcp-config`, `--tools ""` to remove every built-in tool, `--setting-sources`, and `--session-id`/`--resume` (checked on Claude Code 2.1.278).

## 3. Design: two universal ports

```
            ┌───────────── agent checkpoint (unchanged) ─────────────┐
            │ switch → connection → tier → paths → holdout → budget  │
            │ → audit log → handler                                  │
            └──────▲──────────────────────────────────▲──────────────┘
                   │ agent_call                       │ agent_request (per-turn token)
     ┌─────────────┴────────────┐       ┌─────────────┴──────────────────────┐
     │ PORT 1: Model API        │       │ PORT 2: Agent runtime              │
     │ Quantarium runs the loop    │       │ The vendor's own app runs the loop │
     │ protocol: openai-chat    │       │ protocol: acp (universal)          │
     │           anthropic-msg  │       │ profiles: claude-code, codex-exec  │
     │ presets = data           │       │ presets = data                     │
     └──────────────────────────┘       └────────────────────────────────────┘
```

### Port 1 — Model API (Quantarium runs the loop)

- **Two protocol adapters replace the provider adapters:**
  - `openai-chat`: Chat Completions, through the official `openai` SDK with `base_url`;
  - `anthropic-messages`: through the official `anthropic` SDK with `base_url`.

  The v0.3.0 OpenAI and Anthropic connections become presets of these, and existing connections migrate automatically.
- **Connection settings:**
  - protocol and endpoint URL;
  - model;
  - key location: an environment variable, the keychain, or none for local servers;
  - optional extra headers, from an allow-list, so no headers that carry credentials;
  - capability flags found by probing.
- **Presets** are data in one file, `quantarium/assets/agents/presets.json`, so contributors can add a provider without writing Python. Each gives a display name, protocol, endpoint, the usual key variable, a model list or discovery, and a docs link:
  - OpenAI, Anthropic, Gemini, xAI;
  - OpenCode Zen, OpenRouter, Groq, Mistral, DeepSeek, GitHub Models;
  - Ollama, LM Studio, and Custom.
- **Model discovery:** a `GET {endpoint}/models` request lists models where the endpoint supports it. Otherwise the user types a name.
- **Test connection:** one small request with one tool. It shows whether the endpoint and model can call tools, which the assistant needs, and how long the call took. Tool-less models are refused with a clear message.
- **Endpoint safety:**
  - keys are sent only over HTTPS, except to loopback;
  - a key is sent only to the endpoint it was configured with;
  - a non-preset endpoint shows its host before the first request;
  - redirects to another host are not followed with the key;
  - errors never echo keys (the v0.3.0 rule).

### Port 2 — Agent runtime (the vendor's app runs the loop)

- **A generic ACP client** in `quantarium/runtimes/acp.py`. For each turn, Quantarium:
  1. starts the configured command;
  2. calls `initialize`, offering no client file-system or terminal capabilities;
  3. calls `session/new` (or `session/load` when supported), with `mcpServers` set to `quantarium mcp` and a per-turn token;
  4. calls `session/prompt`;
  5. turns `session/update` events into chat blocks.
- **Permission requests decide tool use before it happens.** `session/request_permission` is answered automatically: allowed only for Quantarium's own MCP tools, rejected for everything else. A reported tool call that is not Quantarium's stops the turn, the same backstop as the Codex bridge.
- **Profiles for runtimes that need special handling:**
  - `claude-code`: the unmodified `claude` CLI with `-p --output-format stream-json --mcp-config … --strict-mcp-config --tools ""`;
  - `codex-exec`: the v0.3.0 bridge.

  A profile is a small class behind one interface (start, send turn, parse events, cancel, clean up).
- **Runtime presets** are data too: command, arguments, the setup hint, the vendor's terms note, and whether subscription use is allowed. "Custom ACP agent" takes any command.
- **What every runtime turn guarantees:** a per-turn token; an empty temporary folder; an environment without Quantarium, provider, or broker secrets; the user's own vendor instructions noted (as with `~/.codex/AGENTS.md`); and cleanup of temporary files and, when offered, the vendor's transcript.

### What changes for users

- Settings → Connections gets one form with three choices:
  - **Model API**, with a preset or Custom;
  - **Agent app**, with a preset or Custom ACP;
  - **External agent token**, unchanged.
- Each preset's card says plainly who bills the usage, where conversations are kept, and the vendor's terms status.

## 5. Testing

- **Protocol adapters:** recorded responses for each protocol from a local fake server, including tool-call fragments, refusals, errors, and redirects to another host (the key must not follow). The tests use the real SDKs where installed and skip otherwise, as in v0.3.0.
- **Presets:** a test validates `presets.json` (fields, HTTPS endpoints, known protocols, docs links) so a contributor's preset cannot break the form.
- **ACP client:** a fake ACP agent (like `tests/fake_codex.py`) checks:
  - the initialize capabilities Quantarium offers;
  - the `mcpServers` it passes, including the token;
  - that non-Quantarium tools are denied when the agent asks permission;
  - that an unannounced tool call stops the turn;
  - that the token is withdrawn after the turn;
  - that cancel works.
- **Claude Code profile:** a fake `claude` checks the exact flags (`--tools ""`, `--strict-mcp-config`, the per-turn MCP config). The maintainer runs one real turn on a Claude plan before release, and one per preset in later versions.
- **Parity:** the v0.3.0 test that runs the same tool through MCP and the assistant gains one case per port.

## 6. Decisions

Decided by the user on 2026-10-21:

| Decision | Choice |
| --- | --- |
| Claude subscriptions | Ship in v0.3.1 as **experimental**. Quantarium provides the technical path within what Anthropic's terms describe: the user's own unmodified Claude Code, signed in by Claude Code itself, with Quantarium never handling credentials. Whether to connect a Claude plan, and any consequence for the user's Anthropic account, is the user's decision and responsibility, which they accept explicitly when creating the connection. |
| Copilot and Grok subscriptions | API keys only until their terms clearly allow subscription use from other apps. |
| Codex | Keep the `codex-exec` profile; ACP through `codex-acp` may be added as an option later. |
| Presets | Community-contributed presets are welcome, reviewed like code and checked by a validation test. |

## 7. v0.3.1 as built

- Port 1: `providers.py` (key reading, endpoint checks, Test connection, model listing), the two protocol adapters, presets in `quantarium/assets/agents/presets.json` with `quantarium/presets.py`, and migration of v0.3.0 connections on read ([ADR-0021](../adr/0021-model-api-port.md)).
- Port 2: `quantarium/runtimes/` with the shared turn helpers, `acp.py`, `claude_code.py`, and `codex_exec.py` (moved from `bridges.py`) ([ADR-0022](../adr/0022-agent-runtime-port.md)).
- The Claude Code profile ships as permanently experimental, with the acknowledgement recorded on the connection. It is tested against a stand-in `claude` only; no real turn has been verified, and none is planned. Quantarium provides it as is.
- Deferred: the optional extra-headers allow-list (no preset needed it), and the community preset contribution guide.

## 8. v0.3.2 as built

- Research update: OpenCode's documented endpoint is now `https://opencode.ai/inference/openai/v1` for Chat Completions models, with models listed at `https://opencode.ai/inference/v1/models`. Its free models answer `403 FreeTierError` ("can only be used from within OpenCode") to any other client. So free models are reached only through `opencode acp`, and the API preset is for credits, with discovery off.
- OpenCode's ACP agent (read from its source) registers the MCP servers a client passes in `session/new`. It names their tools `<server>_<tool>`, gives them kind `other`, and asks permission with `allow_once`, `allow_always`, and `reject_once` options. By default OpenCode allows its own tools without asking. The preset's `OPENCODE_CONFIG_CONTENT` turns them off and makes everything else ask.
- Tested against a stand-in agent that behaves like OpenCode's ACP code; not yet run against a real OpenCode install, so the preset is experimental.
- Port 1 verified for real with Ollama (`qwen3:4b`): model listing, Test connection, and two assistant turns that called `list_cells` through the agent checks.

## 9. Copilot skipped; v0.3.3 is Grok

- GitHub Models was retired on July 30, 2026 (its REST docs say the inference API, catalog, and BYOK are gone), so the planned API preset cannot exist.
- The remaining path is Copilot CLI over ACP with a Copilot plan. GitHub's ACP docs name custom frontends and multi-agent systems as uses, but no terms say plainly that another app may use a personal plan this way. The user chose to skip Copilot. Anyone can still connect it as a Custom ACP agent.
- Versions shift down: v0.3.3 is Grok (xAI API key; Grok plans not offered) and v0.3.4 is Gemini.
- Gemini gets an API preset only. A Gemini CLI runtime preset is not offered: Quantarium gives agent apps no `*_API_KEY` variables, so Gemini CLI could fall back to Google-account sign-in, which Google's terms forbid for third-party use.

## 10. v0.3.4 is Gemini; the series is complete

- Gemini model API preset at `https://generativelanguage.googleapis.com/v1beta/openai`, which supports tools and model listing through Chat Completions.
- Shipped: v0.3.1 ports and Claude Code (permanently experimental), v0.3.2 OpenCode, v0.3.3 Grok, v0.3.4 Gemini. Copilot skipped.
- Possible follow-ups: an `openai-responses` protocol, since several vendors now put their newest features there first; and an optional allow-list of extra headers.

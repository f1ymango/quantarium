# Plan: v1.0 — Public release as Quantarium

- **Status:** Accepted (2026-10-26)
- **Roadmap:** [roadmap to v1.0](roadmap-to-v1.md), v1.0

## 1. Decisions

Made with the maintainer on 2026-10-26:

| Topic | Decision |
| --- | --- |
| How the code goes public | **A fresh public repository, `quantarium`**, starting from one clean commit of 1.0.0. The private development repository stays private and untouched as the full archive: its history (including the early watch list), its tags, and its branches with saved market data (`expectations-data`, `ml-review`, `ml-signals`) never become public, and nothing is rewritten. |
| Kandodaki | **Agreed** to PolyForm Noncommercial 1.0.0, with commercial rights kept by the maintainer and Kandodaki, for code adapted from his work (confirmed by the maintainer, 2026-10-26). |
| Contributions | **Ideas only** at 1.0: issues and ideas are welcome; code pull requests are not merged as they are, but generalized by the maintainers. No contributor agreement is needed until that changes. |
| Versions | Decided 2026-10-26 as release candidates; changed 2026-10-27 to **1.0.x steps**: the four candidates are tagged `v1.0.1`–`v1.0.4`, later steps continue from `v1.0.5`, and the public release carries whatever 1.0.x is current ([versioning](../versioning.md)). |
| Name | **Quantarium** (decided 2026-10-24). |
| License | **PolyForm Noncommercial 1.0.0** (decided 2026-10-24). |

## 2. Steps

| Version | Contents |
| --- | --- |
| **v1.0.1 — The rename** | The package, the `quantarium` command, `python -m quantarium`, the app, the MCP server, environment variables (`QUANTARIUM_*`), the workspace folder (`.quantarium`), the workspace file, the token prefix (`qtm_`), the browser token header, and file formats (`quantarium-*-v1`). Workspaces, settings, tokens, files, scripts, and Lab records from before 1.0 keep working. |
| **v1.0.2 — License and public documents** | `LICENSE` (PolyForm Noncommercial 1.0.0, with the required notice naming the copyright holders), `SECURITY.md`, `CONTRIBUTING.md` (ideas only), and a README for strangers: what Quantarium is and is not, a statement that it supplies no market data and gives no financial advice, and screenshots. |
| **v1.0.3 — Packaging** | Package metadata, a built wheel and source archive checked locally (contents, no stray files, installs and runs in a clean environment). Publishing to PyPI is the maintainer's action. |
| **v1.0.4 — Security review** | A review of everything since v0.5 (v0.6 referee, v0.7 evidence, v0.8 engine, v0.9 data, the rename) against the `AGENTS.md` invariants, written up as `docs/security-review-v1.0.md`; each finding fixed with a test, or recorded with its reason. |
| **Later 1.0.x — UI review, then publish** | A script that exports the release tree (tracked files only, no `private/`, no `runs/`, no history) for a first commit in the new repository, and a final checklist. The maintainer creates the public repository, pushes it, makes it public, and publishes to PyPI. |

## 3. Security

- The rename must keep every invariant in `AGENTS.md` section 5 working under both names: tokens checked as SHA-256 whatever their prefix, the secret patterns covering the current and the earlier token prefix, hidden folders refused to agents under both names, and the import guard treating earlier and current module names alike.
- The release export includes only tracked files and is checked with the same secret scan as every commit, plus a scan for personal data.
- GitHub Actions stay off in the new repository unless a reviewed workflow is approved.

## 4. As built

### v1.0.1 (committed as 1.0.0rc1) — The rename

- The package folder moved to `quantarium/`, and every live file (package, tests, tools, examples, README, `AGENTS.md`, `CLAUDE.md`, current docs) took the new names, including the agent token prefix, now `qtm_`. History documents followed in v1.0.8.
- `quantarium/legacy.py` holds every old name: `env()` (both variable prefixes), `is_format()` (both format names, strings only), `current_entrypoint()`, `current_relative()`, `current_value()`, and `migrate_hidden()`. Wired into the workspace (migration, workspace file, `resolve`, scans), the MCP token, agent-app variable scrubbing, the secret pattern, the keychain, every format check, the engine's strategy loader, and the Lab's comparison of saved registrations.
- The package's earlier name is kept as a two-file alias package: a meta-path finder that returns the `quantarium` module object for each of its submodules (never executing it twice), and a `__main__` that runs Quantarium's command line.
- Decided during the step: the old hidden folder is renamed in place rather than copied, so there is one source of truth; when both folders exist the old one is left alone. Saved records are never rewritten, because evidence reports compare their embedded record with the ledger byte for byte.
- Found during the step: the decider check for agent-submitted configs searched the config's text, so a JSON escape (or the old package name through the alias) slipped past it. Fixed to inspect the decoded JSON; the new test failed against the old check on both spellings.
- Tests: `tests/test_legacy.py` (folder migration, both-folders case, workspace file and variables, old formats including evidence reports, old entrypoints and imports, an old `qtm_` token, secret patterns) and the decider escape test.

### v1.0.2 (committed as 1.0.0rc2) — License and public documents

- `LICENSE.md` is `PolyForm-Noncommercial-1.0.0.md` from `raw.githubusercontent.com/polyformproject/polyform-licenses/1.0.0/` (4,563 bytes), downloaded with the maintainer's permission, read in full, and copied unchanged (same SHA-256). The required notice lives in `NOTICE`, so the license text stays verbatim.
- Decided during the step: the notice names the copyright holders by their GitHub names (f1ymango and Kandodaki); the maintainer may replace them with legal names. Vulnerability reports go through GitHub's private reporting, which the maintainer turns on in the new repository's settings; no email address is published.
- Screenshots come from a demo workspace of invented markets and companies (scratch folder, never committed), captured with headless Edge at 1440×900: Home, the Lab, and the imported example index.

### v1.0.3 (committed as 1.0.0rc3) — Packaging

- Built with setuptools 84.0.0 (from August 2026; 84.2.1, the newest, was six days old) installed with `--only-binary=:all: --no-deps` into a scratch build environment; its only `.pth` file is setuptools' standard `distutils-precedence.pth`, read and found to hold no network code. Nothing was installed into the project or the global Python.
- Found during the step: an ignored `build/` folder from an older build put 63 stale files into the wheel. Removed, and the release steps say to remove it; the rebuilt wheel holds 111 `quantarium` files and the 2-file alias.
- The source archive first held part of the tests (none of `tests/security/` or the fakes); `MANIFEST.in` now leaves tests out entirely.
- Smoke test: wheel plus `tzdata==2026.5` (23 days old) in an empty environment, run from a scratch folder: `--version`, the import alias, `run examples/experiment.json`, `data check`, `dashboard`, and `serve --fresh` opened in the browser (no console errors).
- Not done: uploading. `docs/releasing.md` lists the maintainer's steps.

### v1.0.4 (committed as 1.0.0rc4) — Security review

- `docs/security-review-v1.0.md`: scope v0.6 to v1.0.4, three new attackers for a public release (strangers' files, shared reports, the package), eight findings with their fixes and tests, what held, accepted risks, and what remains untested.
- Fixed in this step: path redaction in evidence reports (`evidence.shareable`), the bounded decider reader, the narrower legacy entrypoint pattern, and the refusal to overwrite decision files from the app. Negative checks: the report test and the reader test (80 MB peak with the old reader) fail against the old code.
- `AGENTS.md` gains the token prefixes in its scan list (a strengthening).

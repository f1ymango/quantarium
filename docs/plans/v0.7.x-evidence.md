# Plan: v0.7.x — Evidence you can share

- **Status:** Done: v0.7.0 to v0.7.3 (2026-10-26)
- **Date:** 2026-10-26
- **Roadmap:** [roadmap to v1.0](roadmap-to-v1.md), v0.7

## 1. Goal

Two things a careful reader asks of any trading result, and that Quantarium can answer better than most tools:

1. **"How many tries did it take?"** The best of many tries looks better than it is. Quantarium already counts every Lab attempt per idea and every variant an agent simulates. v0.7 turns those counts into statistics that correct for them.
2. **"Can I check it?"** A verdict should leave the workspace as a single file that shows everything it rests on, and that can be checked against the workspace it came from.

## 3. Statistics in detail

- **Inputs.** Daily returns of the candidate in each scenario, from the Lab's own database. Attempts are the Lab experiments registered for the same idea; for agent-driven work, the connection's variant count is shown beside them.
- **Probabilistic Sharpe ratio** (Bailey and López de Prado, 2012): from the daily Sharpe ratio, the number of sessions, and the skewness and kurtosis of daily returns.
- **Deflated Sharpe ratio** (Bailey and López de Prado, 2014): the probabilistic Sharpe ratio measured against the Sharpe ratio expected from the best of N attempts by chance, where N is the number of attempts and the spread is the variance of their Sharpe ratios. With one attempt it equals the probabilistic Sharpe ratio.
- **Probability of backtest overfitting** (Bailey, Borwein, López de Prado, and Zhu, 2017): the attempts' daily returns on a shared scenario are split into blocks; for every way of choosing half the blocks, the best attempt in that half is ranked in the other half.
- **Limits, stated in every report:** these statistics assume the attempts Quantarium saw are all the attempts. Tries made outside the workspace are invisible to it. Daily returns of a synthetic scenario say nothing about real markets.

## 4. Security

- The report is static: no scripts that load anything, no external resources, and every value from the record rendered as text. A test checks the file for external URLs and for raw HTML from the record.
- `verify-report` parses the embedded JSON with the strict reader, and never runs anything from the file.
- Prices in the bundled table are data, checked like presets; a missing price leaves the grant's own prices required.

## 5. Decisions

Made with the maintainer on 2026-10-26:

1. **The deflated Sharpe ratio gates the verdict.** A "supported" verdict also needs a deflated Sharpe ratio of at least 0.95 in every scenario; below that the verdict is **inconclusive**, with the reason.
2. **A dated price table** ships with Quantarium and fills grants; the user can override it.
3. **Reports are HTML only**, with the record embedded.

## 6. As built

### v0.7.0 — Trial-aware statistics

- `quantarium/trials.py`: `daily_returns` (from a run's valuations, read-only), `moments`, `probabilistic_sharpe`, `expected_maximum_sharpe`, `deflated_sharpe`, and `overfitting_probability` (CSCV over 8 blocks, 70 combinations, ranking by per-session Sharpe ratio). The expected maximum for 100 attempts with unit variance is 2.53, as in the literature.
- `Lab._statistics` gathers the candidate's daily returns per scenario (keyed by the scenario's prices, so a renamed copy matches) for this attempt and every completed earlier attempt at the idea. `trials` is the larger of the attempt number and the attempts with results.
- `Lab._verdict` takes the statistics: a would-be supported verdict with any scenario's deflated Sharpe ratio below 0.95, or none computable, becomes inconclusive. A PBO of 50% or more adds a caveat. The verdict carries `statistics`.
- Records from before v0.7.0 have no statistics; their verdicts are unchanged.

### v0.7.1 — Evidence reports

- `quantarium/evidence.py`: `render(record)` and `verify(page, workspace_root=None)`. The record is embedded in a `<script type="application/json">` block as canonical JSON, with `<`, `>`, and `&` escaped, and its SHA-256 in `data-sha256`. The page's Content-Security-Policy is `default-src 'none'; style-src 'unsafe-inline'`.
- `verify` re-reads the embedded JSON with the strict reader and recomputes the hash; with a workspace it compares the ledger's record and re-hashes scripts, decision files, and scenario prices.
- CLI `quantarium lab report` and `quantarium lab verify-report` (exit status 1 when the page or the ledger do not match). API `GET lab-report/{id}`, not an agent route.

### v0.7.2 — Model costs

- `quantarium/assets/agents/prices.json` (version 1, checked 2026-10-26): Anthropic's Fable 5.1, Opus 5.5, Sonnet 5.5, and Haiku 5.5 (short-prompt rate), and OpenAI's current models at short-context rates, from the providers' pricing pages; `free_presets` for Ollama and LM Studio. `presets.prices()` and `presets.price_for(preset, model)`.
- `Api._grant_ask` fills missing prices from the table and refuses a model it does not list; given prices always win.
- `AgentSettings.set_daily_cost_limit`; `ask.spent_today` sums today's estimated cost for the connection across `.quantarium/tapes/*.jsonl`, and `AskGateway.ask` refuses a new call once the limit is reached.
- The table goes stale as prices change; the date checked is shown with it, and v0.7.3 shows it in the app.

### v0.7.3 — The app

- `pages/lab.js`: `Statistics` (probabilities shown as plain percentages, deflated Sharpe ratios below the threshold marked) and `downloadReport`, which saves the page the server builds (`GET lab-report/{id}`) through a local blob link.
- `pages/cell.js`: `listedPrice` fills a new grant's prices from `GET agents` → `prices`; blank prices are left for the server, which uses the table or asks for them.
- `pages/agents.js`: `DailyLimitField` sets `agent-connection-daily-limit`.
- Handbook topics `trials` and `evidence-report` in the Lab chapter, and feature rows.
- Checked in the browser on a scratch workspace: the statistics table, the report endpoint and its CLI verification, prices filled for Claude Sonnet 5.5 with the table's date, and saving a daily limit.
